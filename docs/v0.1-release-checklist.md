# v0.1 release checklist

Target release: `v0.1.0`  
Status: pre-implementation checklist  
Related issue: [#5](https://github.com/yo4e/WorldSimSeed/issues/5)

This checklist is a release gate, not a promise that every future feature belongs in v0.1.

## Project and legal

- [ ] Maintainer explicitly approves the repository license.
- [ ] `LICENSE` exists and package metadata matches it.
- [x] Contribution policy is documented.
- [x] Security policy is documented.
- [x] Code of Conduct need has been reviewed; separate file is deferred for the current small pre-release phase.
- [x] Changelog and release-versioning policy exist.
- [x] Semantic Versioning policy is documented.

## World-spec contract

- [ ] world spec v0.1 is versioned and documented.
- [ ] JSON/YAML source-of-truth and schema strategy are decided.
- [ ] unsupported/unknown fields have an explicit validation policy.
- [ ] expression operator/function allowlist is documented.
- [ ] state/parameter path rules are documented.
- [ ] arbitrary JavaScript, host-object access, dynamic imports, recursion, and user-defined unbounded loops are not expressible.
- [ ] at least three materially different sample worlds have been checked against the format.

## Runtime and security

- [x] Threat model and trust boundaries are documented.
- [x] Untrusted world specs are the default security assumption.
- [x] Resource-limit categories and ownership are defined.
- [ ] Conservative finite numeric defaults are selected from benchmarks.
- [ ] Runtime enforces agent, step, batch-run, event, and retained-trace/output limits.
- [ ] Host can abort a run.
- [ ] Limit termination returns a clear structured error.
- [ ] Prototype/property escape negative tests exist.
- [ ] Unsupported-operation and malformed-spec negative tests exist.
- [ ] There is no spec-driven network/filesystem/import path.
- [ ] Browser execution strategy prevents long unbounded main-thread blocking.

## Reproducibility

- [ ] Same spec + parameters + engine version + seed has a deterministic result contract.
- [ ] Run manifest records engine version, spec version, spec hash, seed(s), parameters, active limits, observer/trace configuration, and provenance timestamp.
- [ ] Seed derivation for batch runs is documented.
- [ ] Browser and headless execution agree on the required deterministic summary for acceptance fixtures.

## Vertical slice

- [ ] Schema validation works.
- [x] Seeded PRNG works.
- [x] Agents initialize.
- [x] Tick/step advances.
- [x] Probability event executes.
- [x] State update executes.
- [x] Minimal observers return results.
- [x] Headless/Node execution works.
- [x] Reference world runs end to end.

## OSS usability

- [ ] README accurately describes implemented rather than aspirational behavior.
- [ ] Five-minute path exists: inspect sample → edit one parameter → run → inspect result.
- [ ] Installation/run instructions work from a clean environment.
- [ ] At least one embedding example exists if embedding is included in v0.1.
- [ ] Public API surface is documented.
- [ ] Examples and docs match the release tag.

## Quality gate

- [x] Automated tests pass.
- [x] Lint/type checks pass if configured.
- [x] Build/package checks pass.
- [ ] Dependency audit results are reviewed.
- [ ] Security-sensitive negative tests pass.
- [x] No `eval`, `new Function`, or equivalent spec-code execution path exists.
- [ ] Known limitations are documented.

## Release mechanics

- [ ] `CHANGELOG.md` contains the v0.1.0 release notes.
- [ ] Version metadata is set to `0.1.0`.
- [ ] Release commit/tag points to the exact tested revision.
- [ ] Clean install/test is repeated from the tag candidate.
- [ ] GitHub release notes link to docs, examples, security policy, and known limitations.
- [ ] Only after all required gates pass, create the `v0.1.0` release/tag.

No release or tag should be created merely because the documentation checklist exists.
